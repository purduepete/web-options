# Exit-Target Analysis — Spec

Validated 2026-08-19 by GPT-5.5 and Gemini 3.6 Flash (see session for findings). Ready to implement.

## Purpose

Analyze VADER signal history to recommend the take-profit percentage per risk tier that maximizes
credit captured. "Take-profit at X%" means closing the position when X% of the original credit is
kept, i.e., buying back when the option mark falls to `entry_mark × (1 - X)`. Output is an
on-demand HTML report generated by `backend/tools/analyze-exit-targets.ts`.

---

## Data sources (PROD DB, opt schema, read-only)

| Table                         | Role                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `opt.telegram_signal`         | Entry: tier, delta, premium (per-contract), collateral, expiry_date, report_date, contract_key |
| `opt.telegram_entry_quote`    | Actual entry: mark **per share**, actual_delta, is_illiquid_quote                              |
| `opt.telegram_contract_price` | EOD price path: regular_close rows, price_date BETWEEN report_date AND expiry_date             |

Capture start: **2026-08-05**. No backfill possible for earlier dates. Sample grows forward only.

---

## Key invariant: always per-share arithmetic

```
entry_mark_per_share  = q.mark                        (telegram_entry_quote)
fallback_per_share    = s.premium / 100               (VADER states per-contract; normalize)

exit trigger for P:   tcp.mark_per_share <= entry_mark_per_share × (1 - P)
credit captured:      entry_mark_per_share × P × 100  (multiply × 100 at aggregation only)
```

Mixing per-contract credit against a per-share EOD mark would make nearly every trigger look hit.
Keep units consistent throughout.

---

## Contract states (mutually exclusive; check in this order)

| State             | Condition                                                 | Credit counted                                    |
| ----------------- | --------------------------------------------------------- | ------------------------------------------------- |
| closed-with-exit  | first regular_close mark hits trigger before expiry_date  | entry_mark × P × 100                              |
| expired-worthless | expiry_date < today, no trigger hit, final close mark ≈ 0 | entry_mark × 100                                  |
| expired-itm       | expiry_date < today, no trigger hit, final close mark > 0 | (entry_mark − final_mark) × 100 (may be negative) |
| still-open        | expiry_date >= today                                      | EXCLUDED; shown as count                          |
| no-price-path     | zero regular_close rows                                   | EXCLUDED; shown as count                          |

"Final mark" = last regular_close row where price_date <= expiry_date. Do not treat all
non-triggered expired contracts as full-credit — a put expiring ITM is a loss, not a win.

---

## Simulation model

Models a **standing buy-to-close limit order** at the profit target. EOD marks infer the first
calendar day the target was reachable. Intraday touches are invisible; the result is a conservative
lower bound. State this explicitly in the HTML output.

---

## Levels swept

`[0.10, 0.25, 0.50, 0.75, 0.90, 0.95, 1.00]`

P = 1.00 = hold to expiry (trigger can never fire; classified by expired-worthless or expired-itm).

---

## Metrics (show all three; recommend on capture rate %)

| Metric         | Why                                                                                  |
| -------------- | ------------------------------------------------------------------------------------ |
| Capture rate % | sum(captured) / sum(potential credit) — normalized; **primary recommendation basis** |
| Total credit $ | raw dollars — dominated by large-premium contracts; secondary                        |
| Avg days held  | mean(exit_date − report_date); reveals capital-turnover cost of higher targets       |

If a lower level would win on an annualized-credit basis, note it as a secondary observation.

---

## Primary cut: tier. Secondary cut: delta bucket (where n allows)

Delta buckets (telegram_entry_quote.delta preferred; fallback telegram_signal.delta):

| Bucket | Range    |
| ------ | -------- | ----- | -------- |
| Low    | `        | delta | < 0.15`  |
| Mid    | `0.15 <= | delta | < 0.25`  |
| High   | `        | delta | >= 0.25` |

Show a bucket's recommendation only where **n >= 10** closed contracts. Fall back to tier-level otherwise.

## Input filters (mirror SIGNAL_QUERY in backend/src/signals/sql.ts)

```sql
option_right = 'P'
parse_status = 'parsed'
is_current   = 1
report_date >= '2026-08-05'
```

Exclude `is_illiquid_quote = 1` contracts from recommendation totals; show illiquid count separately.

## Query approach (two queries, not N+1)

**Query 1 — contracts:**

```sql
SELECT s.contract_key, s.tier, s.delta vader_delta, s.premium, s.collateral,
       s.expiry_date, s.report_date,
       q.mark  entry_mark_per_share,
       q.delta actual_delta,
       q.is_illiquid_quote
FROM opt.telegram_signal s
LEFT JOIN opt.telegram_entry_quote q
       ON q.contract_key = s.contract_key
      AND q.report_date  = s.report_date
WHERE s.option_right = 'P' AND s.parse_status = 'parsed' AND s.is_current = 1
  AND s.report_date >= '2026-08-05'
```

**Query 2 — price paths (JOIN not IN list — avoids SQL Server 2100-param limit):**

```sql
SELECT tcp.contract_key, tcp.price_date, tcp.mark
FROM opt.telegram_contract_price tcp
INNER JOIN (
    SELECT DISTINCT contract_key, report_date, expiry_date
    FROM opt.telegram_signal
    WHERE option_right='P' AND parse_status='parsed' AND is_current=1
      AND report_date >= '2026-08-05'
) base ON tcp.contract_key = base.contract_key
      AND tcp.price_date BETWEEN base.report_date AND base.expiry_date
WHERE tcp.market_session = 'regular_close'
ORDER BY tcp.contract_key, tcp.price_date ASC
```

## HTML report layout

File: `docs/exit-target-analysis-<YYYY-MM-DD>.html` (regenerated on demand, not committed).
Style: indigo/violet accent, squared corners, dark default plus a light toggle.

Sections:

1. **Summary header** — sample window (2026-08-05 to run date), total contracts, excluded counts
2. **Per-tier table** (one per tier) — rows = level | n closed | capture rate % | total credit $ | avg days held | recommendation badge
3. **Excluded counts table** — per-tier breakdown of all five states
4. **Delta sub-cut** — collapsible per tier, only where n >= 10 per bucket
5. **Disclaimers** — EOD granularity note, capture floor, standing-limit-order model, sample size

## Scope boundaries

- Objective: total credit captured; recommendation uses capture rate % (normalized).
- Primary cut: tier. Secondary: delta (where n allows).
- EOD source: `opt.telegram_contract_price`, regular_close rows only.
- Capture floor: 2026-08-05. No synthetic backfill.
- Out of scope: DTE conditioning, IV, VIX at entry, calls.
- No new DB objects: no writes, no new tables.
- Output: regenerated on demand, not committed to git.
